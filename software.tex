\chapter{Software artifacts}\label{chap:software}

During our research in the area of abstractions for layout- and traversal-agnostic algorithm design in the context of high-performance computing, we have developed two prototype libraries that implement the proposed approaches.

\section{Noarr}\label{sec:sw-noarr}

Noarr\footnote{\url{https://github.com/ParaCoToUl/noarr-structures}} is an open-source \cpptwenty header-only library that provides abstractions for defining and manipulating memory layouts of multidimensional data structures and their traversal patterns, including support for parallel execution. It is the main software artifact for the contributions described in \cref{sec:astute-approach,sec:pure-cpp-approach,sec:cpp-abstractions,sec:layout-agnostic}.

\xxx{The development of Noarr is continuously tested on Linux, Windows, and macOS platforms using the \texttt{gcc}, \texttt{clang}, and \texttt{msvc} compilers of various versions, and it is available under the MIT license with no external dependencies.}

Integration of Noarr into an application requires only including the header file \texttt{noarr/traversers.hpp}. This includes all the necessary components of the library for the functionality described in the aforementioned sections.

The library has two external components: Noarr-tuning\footnote{\url{https://github.com/ParaCoToUl/noarr-tuning}} and Noarr-MPI\footnote{\url{https://github.com/ParaCoToUl/noarr-mpi}} that provide additional functionality discussed in \cref{sec:cpp-abstractions,sec:layout-agnostic}, respectively.


The library is centered around \emph{Noarr structures}, abstractions for memory layouts that are built by composing simpler building blocks called \emph{proto-structures}. In \cref{sec:native-abstractions}, we would categorize Noarr structures (and proto-structures) as an example of \emph{hierarchical views}. Both of these concepts use dimensions named using character literals (e.g., \lstinline{'x'}, \lstinline{'y'}, \lstinline{'z'}), and their whole functionality is resolved at compile time using template metaprogramming to ensure zero runtime overhead.

On top of Noarr structures, the library defines \emph{traversers}, which are abstractions for traversals of layouts defined by Noarr structures. They are used to define various algorithms similarly to how iterators are used to define algorithms on standard containers in the \cpp standard library.
The library provides a set of proto-structures that can be applied to Noarr structures or traversers to define various transformations of the given layout or traversal, potentially optimizing them for specific hardware architectures.

Traversers are then used to parallelize a given algorithm using various parallel models, such as OpenMP, \cpp threads, threading building blocks, and CUDA\@; or to distribute data across multiple nodes using MPI (using the Noarr-MPI component).

The library allows users to abstract away the details of memory layouts and traversal patterns when defining parallel and distributed algorithms, enabling them to use tools such as autotuning to choose the best combination of layouts and traversals for a given hardware architecture without changing the algorithmic logic. Details of Noarr structures, traversers, and the various transformations that can be applied to them are described in \cref{chap:noarr}.

\section{Cellato}\label{sec:sw-cellato}

Cellato\footnote{\url{https://github.com/matyas-brabec/2026-cellato-journal}} is an open-source \cpptwenty header-only library that defines an embedded domain-specific language for describing the computation of a single cell in a Cellular Automaton, and a subsequent evaluation using a combination of an \emph{evaluator}, \emph{memory layout}, and \emph{traverser}. It supports CPU and GPU execution. The library is available under the MIT license with no external dependencies.

The repository contains the artifacts for an unpublished (as of the time of writing) extension of the work described in \cref{sec:stencil-computations}, which implements \emph{bit-planes} encoding along with bit-wise evaluation as an alternative to the \emph{bit-packing} encoding described in the original contribution.

The approach of the Cellato library can be categorized as an example of an abstraction for \emph{separating computation logic} from concerns related to data layouts and traversal patterns, as described in \cref{sec:native-abstractions}. The central concept is the abstract cell computation specification, which is defined via pre-built nodes by the user. The resulting specification is encoded in compile-time as a hierarchical structure of nodes, similarly to an abstract syntax tree for a programming language. Each node represents a specific operation, such as a binary operation (e.g., addition, multiplication), a unary operation (e.g., negation), or a terminal node representing a cell state or a constant value.

The memory layout component specifies the encoding of the state of the cellular automaton, including the bit-packing and bit-planes encodings. These layouts are applicable to arbitrary cell computation specifications.

The evaluator component specifies how each node used in the cell computation specification is mapped to a specific value calculation. Its implementation is tightly coupled with the memory layout to exploit the specific encoding of the state. The evaluator is essentially a stateless visitor (dispatched using template specializations at compile-time) that traverses the hierarchical structure of nodes representing the cell computation specification and propagates the calculated values from the terminal nodes to the root node, which represents the final value of the cell state after the computation. Each evaluation performed by the evaluator is parametrized by the memory layout and the cell coordinates so that the evaluator can load cell states from the grid for the appropriate terminal nodes.

The traverser component is decoupled from the other components and defines the order of evaluation of the cells in the grid, including support for various parallel execution models and temporal blocking of evaluations. It is applicable to arbitrary cell computation specifications and memory layouts.

The library enables users to define the cell computation logic independently of the memory layouts, evaluation strategies, and traversal patterns, allowing for flexible experimentation with different combinations of these aspects to optimize the performance of cellular automaton simulations on target hardware architectures.
