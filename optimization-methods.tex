As discussed in \cref{chap:code-optimization}, code optimization is crucial for achieving efficient execution of programs on modern hardware architectures such as multi-core CPUs and GPUs. In this chapter, we outline several prominent optimization methods and frameworks that have been developed to facilitate (automated) code optimization in high-performance computing applications.

Code optimization methods can target different points in the compilation and execution pipeline --- some methods operate above the source code level, providing abstractions or domain-specific languages (DSLs) that allow developers to express computations in a way that is amenable to optimization. Other methods perform optimizations at the source code level, possibly using annotations or pragmas to guide the optimization process. More low-level methods operate on intermediate representations (IRs) or directly on machine code, applying transformations to improve performance based on static analysis or empirical measurements. Some methods may also involve runtime systems that adaptively optimize code during execution based on observed performance characteristics; in such cases, methods like just-in-time (JIT) compilation techniques may be employed to generate optimized code on-the-fly based on the current execution patterns.

We primarily focus on abstractions and frameworks that operate above or at the source code level, as these are most relevant to our work. However, we also briefly discuss the wider landscape of optimization methods to provide context for our contributions.

Compiler optimizations are a fundamental aspect of modern compilers. In high-performance computing, compilers such as LLVM~\cite{lattner2004llvm} and GCC~\cite{gcc} implement a wide range of optimization techniques to improve the performance of source code, starting from basic optimizations that remove abstractions and redundant computations, inline functions, perform sub-expression elimination, etc. More advanced optimizations include loop transformations (e.g., loop unrolling, loop fusion, invariant code motion), vectorization, and inter-procedural optimizations that analyze and optimize across function boundaries.

In the context of typical high-performance (scientific computing) applications with quite simple control flow and heavy numerical computations, these optimizations mainly allow using higher-level abstractions (e.g., \cpp templates, mdspan, \ldots) without significant performance penalties (most notably, when using so-called zero-cost abstractions)\xxx{ TODO: cite}. They can also optimize arithmetic expressions, eliminate redundant computations, and perform some basic loop transformations. However, these optimizations by themselves are often insufficient to achieve optimal performance on modern hardware architectures, especially for complex loop nests and data access patterns.

Some compilers and frameworks, such as MLIR~\cite{lattner2021mlir}, provide extensible intermediate representations that allow for custom representation and optimization passes to be implemented --- some of them targeting specific domains or hardware architectures. This is particularly useful for domain-specific languages (DSLs) that can leverage MLIR to implement their own optimization pipelines, including polyhedral optimizations, autotuning, and other transformations that are not typically part of general-purpose compilers. While it is built on top of traditional SSA-based IRs, it allows for defining custom dialects, and facilitates all boilerplate such as parsing, code generation, and so on. Flexible abstractions allowing manipulation of data layouts and iteration orders have been the subject of extensive development. They provide a means to optimize performance to different hardware architectures without needing to change the core algorithmic logic. These abstractions can also represent flexible API layers for libraries (such as linear algebra libraries; TODO cite).

We can broadly categorize these abstractions into the following groups:

\begin{description}
  \item[Domain-specific languages (DSLs):]\label{des:dsl} These are specialized programming languages designed to express computations in specific domains, such as image processing (Halide~\cite{ragan2013halide}), tensor computations (Tiramisu~\cite{baghdadi2019tiramisu}), or array programming (Futhark~\cite{henriksen2017futhark}). They rely on sophisticated compilers or runtime systems to generate optimized code for the target hardware. These DSLs often sacrifice some generality for better analysis and optimization opportunities --- for example, Halide has a fixed computation model based on pipelines of processing stages that has limited expressivity for nested control flow or data-dependent computations.
  \item[Annotation-based tools:]\label{des:annotation-based-tools} These tools, relying on compiler extensions or external preprocessors, allow developers to annotate their code with optimization directives. Examples include OpenMP for parallelization and pragmas for loop transformations. Compared to DSLs, these tools operate on top of the target language (e.g., C/\cpp) and maintain higher generality, or at least compatibility with the host language. However, they may be also limited by specific semantics of the host language. % TODO: remove contradictions etc

  \item[Parallelization frameworks and libraries:]\label{des:parallelization-frameworks} These frameworks provide abstractions enabling developers to run computations in parallel using high-level constructs. Examples include Kokkos~\cite{trott2021kokkos}, RAJA~\cite{beckingsale2019raja}, and SYCL/DPC++.% TODO: maybe more yapping to balance the other items

These abstractions play a crucial role in optimizing applications for modern high-performance computing, as the scale and complexity of diverse hardware architectures continue to grow and traditional low-level optimization techniques are not sufficient to achieve optimal performance. The abstractions enable developers to apply optimizations based on domain knowledge, empirical performance data, or autotuning techniques. Compared to hand-tuned low-level code, maintainability and portability of high-level abstractions is significantly better and the development time is reduced. Many of these abstractions also support advanced validation of correctness of the code transformations.
