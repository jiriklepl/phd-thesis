\chapwithtoc{Introduction}\label{chap:introduction}

% Code optimization is a fundamental aspect of software development in high-performance computing (HPC). Modern HPC systems have complex architectures with hierarchies of memory and processing units, making careful choices of data layouts in memory and traversal orders in algorithms crucial for achieving efficient execution.

% The difference between a na\"{\i}ve implementation and an optimized one can lead to orders-of-magnitude improvements in execution time, runtime resource utilization, and energy efficiency~\cite{hennessy2019computer,drepper2007every}. Thus, if an algorithm is not properly tuned to the specific system it runs on, its execution can waste a tremendous amount of time and energy.

There are many factors that affect the performance of an algorithm on modern high-performance computing (HPC) architectures, such as algorithmic complexity, the choice of data types and instructions, and the arithmetic intensity of computations. We primarily focus on memory access patterns, which are fundamental to optimizing algorithm performance, as many algorithms are bottlenecked by memory bandwidth and latency~\cite{hennessy2019computer,drepper2007every}. This issue becomes more pronounced as the volume of processed data and the scale of parallelism in modern HPC systems increase; parallel execution often requires data communication and synchronization between processing units, leading to additional overheads.

% We explore approaches to transforming data layouts and traversal orders that enable separation of these concerns from other aspects of algorithm design directly in the source code, and thus can be applied to a wide variety of algorithms without compromising further optimization opportunities.

% Optimizing data access patterns is important primarily because modern HPC architectures have specialized hardware features that improve the performance of specific access patterns.
An important aspect of efficient data access patterns is good locality of reference, which means that data accesses are organized in such a way that accesses to nearby data points occur within short time intervals. Similarly, certain access patterns allow for better exploitation of parallelism. Thus, carefully choosing data layouts and their corresponding traversal orders is crucial for achieving efficient algorithm execution on modern HPC architectures.

Even simple data structures, such as matrices, can be stored in a variety of memory layouts. In a row-major layout, elements of each row of the matrix are stored contiguously; in a column-major layout, elements of each column are stored contiguously. If an algorithm traverses a matrix row by row, it accesses the elements sequentially in the row-major layout, while it tends to access them with a larger stride in the column-major layout, leading to poorer locality of reference.

% Many features of modern HPC architectures benefit from accessing data in a contiguous way. For example, CPU caches store multiple consecutive data elements together in a single addressable unit called a cache line for faster access during computation, making the row-major layout significantly more efficient for the row-wise traversal than the column-major layout.
Modern systems also provide many independent processing units that can operate in parallel. For parallel execution, data layouts and traversal orders should be designed so that each unit can access the data it needs with minimal interference from other units~--- avoiding unnecessary communication, synchronization, and write conflicts.

Since contemporary CPU and GPU architectures benefit from different access patterns, and algorithms typically access multiple data structures in multiple ways, choosing appropriate data layouts and traversal orders is challenging and often requires empirical experimentation. Furthermore, different architectures may require different choices for optimal performance, making it difficult to design a single implementation that runs efficiently across architectures without significant redesign.

Many tools and frameworks have been developed to help design and optimize applications for different hardware architectures, such as polyhedral model-based optimizers, autotuning frameworks, and domain-specific languages for various areas of scientific computing~\cite{bondhugula2008pluto,ansel2014opentuner,ragan2013halide,baghdadi2019tiramisu}. However, such tools are often limited to particular classes of algorithms, programming models, or target domains, and they do not always expose optimization transformations to users in a clear and intuitive way.

Our contributions explore two complementary directions:
\begin{inparaenum}[(i)]
\item abstraction design for separating algorithmic logic from data layout and traversal optimizations, and
\item the potential of large language models (LLMs) to assist with algorithm design and optimization.
\end{inparaenum}
Both directions are motivated by the goal of making algorithm optimization more accessible and automatable while improving the performance and portability of scientific applications on modern HPC architectures.

We introduce \emph{layout-agnostic} and \emph{traversal-agnostic} abstractions that allow users to express algorithmic logic independently of specific data layouts and traversal orders, enabling users to design and optimize these aspects separately.
Our approach is based on the composition of small, reusable, and semantically intuitive building blocks that can express a wide variety of data layout and traversal transformations. We demonstrate the applicability of this approach to general scientific computing on CPU, GPU, and distributed architectures, and to domain-specific algorithms such as stencil computations.

We then study the potential of LLMs to assist with code optimization, focusing on their ability to design efficient GPU code and on how abstractions for user-directed optimization affect their code generation. In both areas, we identify key limitations, practical opportunities, and directions for future research.
