\chapwithtoc{Introduction}

Code optimization is a fundamental aspect of software development required to run applications efficiently on modern systems. In the domain of scientific and numerical computations, careful choice of data layouts in memory and traversal orders in algorithms can lead to orders of magnitude improvements in execution time, runtime resources utilization, and energy efficiency~\cite{hennessy2019computer,drepper2007every}.

Two of the most significant factors behind the performance impact of data layouts and traversal orders are memory accesses and data dependencies. Memory accesses (reads and writes) may be subject to very different latencies and bandwidths depending on the order in which they are performed --- for example, most architectures employ caches to improve the performance of repeated accesses to the same or nearby memory locations, and many architectures provide specialized units for operating on data stored in sequential memory locations.
% \xxx{On modern systems, there are many different hardware features that influence the performance based on the memory access patterns in a program.}

A simple example is traversing a row-major matrix by rows rather than by columns: the former tends to access contiguous memory locations and therefore uses caches and vector units more efficiently~\cite{drepper2007every}.

% While there are many formal approaches to code optimization in code compilation toolchains, ...
While tools such as compilers can perform many optimizations automatically, optimal performance often requires specific data layouts and traversal orders that may not be discoverable by compilers due to many factors such as difficulties in proving semantic equivalence of transformations, intricacies of the effects of transformations on performance, and the number of possible transformations and their combinations~\cite{bacon1994compiler,allen2001optimizing}.

Many frameworks and tools such as polyhedral model-based optimizers, autotuning frameworks, and domain-specific languages for various areas of scientific computing have been developed to help design and optimize applications to different hardware architectures~\cite{bondhugula2008pluto,ansel2014opentuner,ragan2013halide,baghdadi2019tiramisu}. Still, such tools are often limited in their applicability to algorithms and do not expose the optimization transformations to users in clear and intuitive ways~\xxx{(CITE)}. Our contributions explore two complementary approaches to help with data layout and traversal optimization: \xxx{cite the works here?}

\begin{itemize}
  \item We have explored the design of flexible abstractions that separate the algorithmic logic of applications from the data layout and traversal optimizations, where both algorithmic logic and optimizations are expressed in the same high-level language and can be designed and optimized independently, also allowing users to easily extend the set of building blocks for both algorithmic logic and optimizations.
  \begin{itemize}
    \item One branch targets general scientific computing. Its proof-of-concept implementation is referred to as Noarr. It is based on layout-agnosticism, which separates the logical (semantic) structure of data (its dimensions and their relationships, sometimes called the \emph{shape}) from the physical structure of data in memory (where each individual element is located).

    Our approach differs from similar approaches in this domain in that it is based on composition of small, reusable, and extensible building blocks that can be used to express a wide variety of data layouts and traversal orders in a semantic and intuitive way (such as tiling or slicing); more specifically, Noarr uses the same building blocks to express both data layouts and traversal order transformations. Thus, it provides a powerful and flexible alternative to popular approaches such as the polyhedral model~\cite{feautrier1992some,bondhugula2008pluto}.
    \item The other branch of our work on abstractions targets the domain of discrete stencil computations, with a proof-of-concept implementation referred to as Cellato. It follows a component-based design, which strictly separates different aspects of a computation (algorithmic logic, data layout, traversal order, parallelization strategy, etc.) into separate components that can be independently designed and optimized. In this approach, the algorithm is expressed as a simple update function that is oblivious to the data layout and traversal order (thus, layout-agnostic and traversal-agnostic).

    Cellato explores a domain that is at this point not well supported by existing tools and frameworks. While there are many tools (including abstractions) for stencil computations, they do not offer flexibility in data layouts specific to discrete stencils, such as bit-level encodings~\xxx{(CITE)}.
  \end{itemize}
  \item Finally, we have explored the potential of Large Language Models (LLMs) to assist with code optimization in the domain of scientific computing. We have focused on two key aspects of this problem:
  \begin{itemize}
    \item The ability of LLMs to generate efficient code under prompts of different specificity, ranging from high-level requests to optimize a given algorithm for a target hardware architecture to prompts that directly prescribe key design decisions for that algorithm and architecture.
    \item The interoperability of LLMs with the abstractions for user-directed code optimization. Since LLMs are based on natural language processing, we study whether the same abstractions that are designed to be intuitive and user-friendly for human users also benefit LLMs in generating efficient code.
  \end{itemize}
\end{itemize}

In all of these approaches, we have made novel findings that contribute to the state of the art in code optimization and algorithm design for scientific computing. Our work on abstractions explores new approaches that either provide alternatives to less intuitive mathematical models with strict assumptions or target underexplored domains, while our exploration of LLM usage addresses research questions that are currently not well understood in the community.
