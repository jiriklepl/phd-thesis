\section{Cellato Library}\label{chap:cellato}

The Cellato library applies the layout-agnostic design principles of Noarr to the domain of cellular automata --- discrete iterative computations on structured grids, where each cell's state is updated based on the states of its neighbors. In this domain, high-performance implementations often employ highly specialized encodings and data representations that are tightly coupled with the computation logic, making it difficult to experiment with different optimization strategies. Cellato addresses this by providing abstractions that separate the automaton's update rules from the underlying data layout, traversal strategy, and per-cell evaluation method.

In our ongoing research in the area of cellular automata, we have observed that many well-optimized implementations share common design patterns such as bit-packing of cell states, temporal blocking of updates, and bit-level SIMD parallelism of cell update computations. Inspired by these observations and layout-agnostic paradigms explored in the Noarr library, we have developed the Cellato library~\cite{brabec2025cellato}, which enables the separation of concerns between the high-level definition of cellular automata and low-level details such as data layouts, parallelization strategies, and computation optimizations.

\subsection{Cellato traversers and evaluators}\label{sec:cellato-evaluators}

% Cellato overview
The Cellato framework is built around the following core abstractions:
\begin{description}
  \item[Algorithm:]\label{des:algorithm} an abstract definition of the cellular automaton update rules pertaining to a single cell, depending on its neighborhood.
  \item[Layout:]\label{des:layout} a grid data structure managing the storage of cell states.
  \item[Evaluator:]\label{des:evaluator} a visitor-style abstraction that applies the algorithm to a single cell, given access to its neighborhood via the layout interface.
  \item[Traverser:]\label{des:traverser} a wrapper around the layout that applies the given evaluator to each cell in the grid.
\end{description}

Traversers define the high-level execution strategy, such as parallelization and temporal blocking, while evaluators encapsulate the low-level cell update logic (for example, interpreting summations of neighboring cells in the algorithm as networks of bitwise operations).

The framework leverages \cpp template meta-programming by encoding the algorithm as a static type consisting of nested nodes representing operations, data accesses, and constants. The evaluator comprises a set of specializations for each node type that, given access to the layout, evaluates to the result of the operation. All these components are further described in detail in~\cite{brabec2025cellato}.

The design consisting of primitive composable building blocks follows the same general principles as the Noarr library, specialized to the domain of discrete iterative stencil computations. We have shown that Cellato can achieve performance comparable to hand-written implementations with less effort. Most importantly, writing the automaton logic in Cellato is agnostic in terms of data layout, traversal strategy, and per-cell computation, enabling rapid experimentation with different optimizations and parallelization strategies.


\subsection{Bit-level optimizations}\label{sec:cellato-bit-optimizations}

One of the key results of our research with Cellato is the ability to encode cell states in a compact bit-packed format, allowing for significant memory bandwidth savings as well as enabling bit-level SIMD parallelism, which performs better than byte-level SIMD for automata with a small number of states per cell and simple update rules.

Since the cell states or the intermediate results of the update computations (such as neighborhood sums) often occupy more than one bit, Cellato provides abstractions for bit-level operations on two representations. The first is the AoS layout (called \emph{bit arrays} in Cellato terminology), where each cell's bits are stored contiguously. The second is the SoA layout (called \emph{bit planes} in Cellato terminology)\footnote{AoS and SoA layouts are described in \cref{sec:memory-layout-optimizations}.}, where each bit plane contains bits of the same significance for all cells.

Both representations can store up to $n$ $k$-bit cells in $n k / w$ machine words, where $w$ is the machine word size in bits (typically 32 or 64). Each layout comes with its own trade-offs.

The bit arrays layout (AoS) is more intuitive to work with and allows operations such as addition and multiplication, provided that the result fits within the available number of bits per cell. However, it can be quite inefficient for storing values that are not powers of two, as each word then contains only $\lfloor w / k \rfloor$ cells with $k$ bits each and has $w \bmod k$ padding bits that are wasted.

In contrast, the bit planes layout (SoA) can store arbitrary bit-width values without any padding, as each plane contains one bit per cell and the total number of planes corresponds to the number of bits per cell. However, operations are limited to bitwise logical operations (AND, OR, XOR, NOT) and bit shifts.

The bit-plane representation then also enables different tile-major encodings, where each tile contains a small rectangular block of cells stored in a contiguous set of words, which can improve memory access patterns and cache utilization for certain automata. Cellato supports various tile sizes $t_w \times t_h = w$, where $w$ is the machine word size in bits, allowing for flexible trade-offs between memory access patterns and implementation complexity.

Compared to other state-of-the-art frameworks for cellular automata, Cellato demonstrates competitive performance while providing a high level of abstraction and flexibility. Compared to hand-optimized implementations using bit-level computations and equivalent encodings, Cellato achieves similar performance with significantly less development effort.


\subsection{Summary}\label{sec:cellato-summary}

Cellato demonstrates that the layout-agnostic and traversal-agnostic design principles explored in the Noarr library can be effectively specialized to the domain of cellular automata. By separating the automaton's update rules from the data layout, traversal strategy, and per-cell evaluation method, Cellato enables rapid experimentation with different optimization strategies --- including bit-packed encodings and various tiling schemes --- without modifying the core automaton logic. This separation of concerns reduces development effort while achieving performance competitive with hand-optimized implementations.
