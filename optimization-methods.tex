As discussed in \cref{chap:code-optimization}, code optimization is crucial for achieving efficient execution of programs on modern hardware architectures such as multi-core CPUs and GPUs. In this chapter, we outline several prominent optimization methods and frameworks that have been developed to facilitate (automated) code optimization in high-performance computing applications, putting particular emphasis on those that are relevant to our work targeting data layout and traversal optimizations.

Code optimization methods can target different points in the compilation and execution pipeline --- some methods operate above the source code level, providing high-level abstractions or domain-specific languages (DSLs) that allow developers to express computations in a way that is amenable to more powerful optimizations. Other methods perform optimizations at the source code level, possibly using annotations or pragmas to guide the optimization process. More low-level methods operate on intermediate representations (IRs) or directly on the generated machine code, applying transformations to improve performance based on static analysis or empirical measurements. Some methods may also involve runtime systems that adaptively optimize code during execution based on observed performance characteristics; in such cases, methods like just-in-time (JIT) compilation techniques may be employed to generate optimized code on-the-fly based on the current execution patterns.

We primarily focus on abstractions and frameworks that operate above or at the source code level, as these are most relevant to our work. However, we also briefly discuss the wider landscape of optimization methods to provide context for our contributions.

Compiler optimizations are a fundamental aspect of modern compilers. In high-performance computing, compilers such as LLVM~\cite{lattner2004llvm} and GCC~\cite{gcc} implement a wide range of optimization techniques to improve the performance of source code, starting from basic optimizations that remove abstractions and redundant computations, inline functions, perform sub-expression elimination, etc. More advanced optimizations include loop transformations (e.g., loop unrolling, loop fusion, invariant code motion), vectorization, and inter-procedural optimizations that analyze and optimize across function boundaries.

In the context of typical high-performance (scientific computing) applications with quite simple control flow and heavy numerical computations, these optimizations mainly allow using higher-level abstractions (e.g., \cpp templates, mdspan, \ldots) without significant performance penalties (most notably, when using so-called zero-cost abstractions~\cite{stroustrup2012foundations}). They can also optimize arithmetic expressions, eliminate redundant computations, and perform some basic loop transformations. However, these optimizations by themselves are often insufficient to achieve optimal performance on modern hardware architectures, especially for complex loop nests and data access patterns.

Some compilers and frameworks, such as MLIR~\cite{lattner2021mlir}, provide extensible intermediate representations that allow for custom representation and optimization passes to be implemented --- some of them targeting specific domains or hardware architectures. This is particularly useful for domain-specific languages (DSLs) that can leverage MLIR to implement their own optimization pipelines, including polyhedral optimizations, autotuning, and other transformations that are not typically part of general-purpose compilers. While it is built on top of traditional SSA-based IRs, it allows for defining custom dialects, and facilitates all boilerplate such as parsing, code generation, and so on. % Note: Halide and Tiramisu do NOT use MLIR; they have their own IRs. MLIR is used by e.g., IREE, Torch-MLIR, Polygeist~\cite{moses2021polygeist}.

Workloads comprising nested loops with affine bounds and affine memory accesses (Static Control Parts, or SCoPs) are common in high-performance computing applications (see, e.g., \citeauthor{bacon1994compiler}~\cite{bacon1994compiler}). To target such applications, \citeauthor{feautrier1992some}~\cite{feautrier1992some} and others pioneered the use of the polyhedral model to represent and optimize computations in loop nests. Polyhedral optimization frameworks, such as Polly~\cite{grosser2012polly}, GRAPHITE~\cite{trifunovic2010graphite}, and PLuTo~\cite{bondhugula2008pluto}, use the powerful mathematical framework of polyhedral model (provided by libraries such as ISL~\cite{verdoolaege2010isl}) to represent the computations in loops in a more compact and analyzable form compared to traditional compiler IRs such as Static Single Assignment (SSA) forms. Polyhedra offer a way to represent data layouts, loop iteration spaces, and dependencies between computations in a unified manner.

Polyhedral optimization is application of integer linear algebra to optimize loop nests with affine bounds and affine memory accesses. The main idea is to represent the iteration space of loops, as well as memory accesses and dependencies, using polyhedra. This representation allows, for example, to find hyperplanes orthogonal to data dependencies, that can represent parallelizable loops; or to find transformations of the iteration space that improve data locality or enable vectorization.

Flexible abstractions allowing manipulation of data layouts and iteration orders have been the subject of extensive development. They provide a means to optimize performance to different hardware architectures without needing to change the core algorithmic logic. These abstractions can also represent flexible API layers for libraries (such as linear algebra libraries; TODO cite).

We can broadly categorize these abstractions into the following groups:

\begin{description}
  \item[Domain-specific languages (DSLs):]\label{des:dsl} These are specialized programming languages designed to express computations in specific domains, such as image processing (Halide~\cite{ragan2013halide}), polyhedral code generation (Tiramisu~\cite{baghdadi2019tiramisu}), or array programming (Futhark~\cite{henriksen2017futhark}). They rely on sophisticated compilers or runtime systems to generate optimized code for the target hardware. These DSLs often sacrifice some generality for better analysis and optimization opportunities --- for example, Halide has a fixed computation model based on pipelines of processing stages that has limited expressivity for nested control flow or data-dependent computations.
  \item[Annotation-based tools:]\label{des:annotation-based-tools} These tools, relying on compiler extensions or external preprocessors, allow developers to annotate their code with optimization directives. Examples include OpenMP for parallelization and pragmas for loop transformations. Compared to DSLs, these tools operate on top of the target language (e.g., C/\cpp) and maintain higher generality, or at least compatibility with the host language. However, they may be also limited by specific semantics of the host language. % TODO: remove contradictions etc
  % TODO: the following name is not final (was named "Native tools" in the abstractions paper; I am thinking about breaking it into two categories: parallelization frameworks and libraries vs _something_ abstractions)
  \item[Parallelization frameworks and libraries:]\label{des:parallelization-frameworks} These frameworks provide abstractions enabling developers to run computations in parallel using high-level constructs. Examples include Kokkos~\cite{trott2021kokkos}, RAJA~\cite{beckingsale2019raja}, and SYCL/DPC++~\cite{khronos2023sycl}.% TODO: maybe more yapping to balance the other items

These abstractions play a crucial role in optimizing applications for modern high-performance computing, as the scale and complexity of diverse hardware architectures continue to grow and traditional low-level optimization techniques are not sufficient to achieve optimal performance. The abstractions enable developers to apply optimizations based on domain knowledge, empirical performance data, or autotuning techniques. Compared to hand-tuned low-level code, maintainability and portability of high-level abstractions is significantly better and the development time is reduced. Many of these abstractions also support advanced validation of correctness of the code transformations.


\subsection{Domain-specific languages (DSLs)}\label{sec:dsls}

Halide~\cite{ragan2013halide} is a C++-embedded DSL with a custom compiler and runtime system that primarily targets image and array processing applications (including regular stencil computations). It is based on defining pipelines of processing stages, where each stage represents a computation that can be optimized independently. The resulting computation pipeline is a directed acyclic graph (DAG) of stages that are subject to various transformations, such as tiling, fusion, and parallelization. These transformations can be guided by the developer using a scheduling language or by autotuning techniques. The Halide compiler performs various checks to ensure that each transformation preserves the semantics of the original computation. It uses interval analysis, which is a less expressive but more powerful (for the target domain) representation than the polyhedral model. Halide's design allows for a high degree of optimization at the cost of expressivity, as it is not suitable for more complex computations, such as those that contain imperfectly nested loops or data-dependent control flow, or non-rectangular iteration spaces.

Exo~\cite{ikarashi2022exocompilation} is Python-embedded DSL that generates C code for specialized hardware. The target-specific instructions and optimization transformations performed on them are all defined in extensible user-level libraries. Similarly to Halide and Tiramisu, the transformations are guided by the developer using a scheduling language. Exo then performs various checks based on effect analysis to ensure program equivalence and memory safety throughout the transformations.
