\chapter{Software artifacts}\label{chap:software}

During our research in the area of abstractions for layout- and traversal-agnostic algorithm design in the context of high-performance computing, we have developed two prototype libraries that implement the proposed approaches.

\section{Noarr}\label{sec:sw-noarr}

Noarr\footnote{The library is available at \url{https://github.com/ParaCoToUl/noarr-structures} along with the documentation and examples for its usage.} is an open-source \cpptwenty header-only library that provides abstractions for defining and manipulating memory layouts of multidimensional data structures and their traversal patterns, including support for parallel execution. It is the main software artifact for the contributions described in \cref{sec:astute-approach,sec:pure-cpp-approach,sec:cpp-abstractions,sec:layout-agnostic}.

Noarr is continuously tested on Linux, Windows, and macOS platforms using various versions of the \texttt{GCC}, \texttt{Clang}, and \texttt{MSVC} compilers, and it is available under the MIT license with no external dependencies.

Integration of Noarr into an application requires only including the header file \texttt{noarr/traversers.hpp}. This includes all the necessary components of the library for the functionality described in the aforementioned sections.

The library has two external components, Noarr-tuning\footnote{Available at \url{https://github.com/ParaCoToUl/noarr-tuning}} and Noarr-MPI\footnote{Available at \url{https://github.com/ParaCoToUl/noarr-mpi}}, which provide functionality discussed in \cref{sec:cpp-abstractions,sec:layout-agnostic}, respectively.


The library is centered around \emph{Noarr structures}, abstractions for memory layouts that are built by composing simpler building blocks called \emph{proto-structures}. In \cref{sec:native-abstractions}, we would categorize Noarr structures (and proto-structures) as an example of \emph{hierarchical views}. Both concepts use dimensions named mainly by character literals (e.g., \lstinline{'x'}, \lstinline{'y'}, \lstinline{'z'}). The dimension names and dispatch of all functions are resolved at compile time using template metaprogramming to avoid runtime overhead.

In addition to Noarr structures, the library defines \emph{traversers}, which are abstractions for traversals of layouts defined by Noarr structures. They are used to define various algorithms, similarly to how iterators are used to define algorithms on standard containers in the \cpp standard library. The library provides a set of proto-structures that can be applied to Noarr structures or traversers to define various transformations of the given layout or traversal, potentially optimizing them for specific hardware architectures.

Traversers are then used to parallelize a given algorithm using various parallel models, such as OpenMP, \cpp threads, Intel Threading Building Blocks, and CUDA\@, or to distribute data across multiple nodes using MPI (using the Noarr-MPI component).

The library allows users to abstract away the details of memory layouts and traversal patterns when defining parallel and distributed algorithms, enabling them to use tools such as autotuning to choose the best combination of layouts and traversals for a given hardware architecture without changing the algorithmic logic.

\section{Cellato}\label{sec:sw-cellato}

Cellato\footnote{The library is available at \url{https://github.com/ParaCoToUl/cellato} along with the documentation and examples for its usage.} is an open-source \cpptwenty header-only library that defines an embedded domain-specific language (DSL) for describing the computation of each cell in a cellular automaton (\cref{sec:stencil-computations}) and for evaluating it using a combination of an \emph{evaluator}, \emph{memory layout}, and \emph{traverser}~--- each of these components provides a specific implementation of a given aspect of the algorithm. The approach of the Cellato library can be categorized as an abstraction for \emph{separating computation logic} from concerns related to data layouts and traversal patterns, as described in \cref{sec:native-abstractions}.

The library is available under the MIT license with no external dependencies other than the \cpp standard library and the CUDA runtime library (for GPU support).

The central concept of the library is the abstract cell computation specification, defined by the user via the \emph{Cellato DSL}. This specification is independent of specific memory layouts and encodings, evaluation strategies, and traversal patterns. The library can use this specification to parallelize the computation on a given CPU or GPU backend, evaluating the cell states using templated components provided by the library.

The \emph{memory layout} component specifies the encoding of the cellular automaton state and the layout of the grid. Most notably, it defines the bit-array and bit-plane encodings, which allow for space-efficient storage of the cell states, improving memory bandwidth utilization and cache locality.

% The \emph{evaluator} component specifies how each node used in the cell computation specification is mapped to a specific value computation. Its implementation is tightly coupled with the memory layout to exploit the specific encoding of the state. The evaluator is essentially a stateless visitor (dispatched using template specializations at compile time) that traverses the hierarchical structure of nodes representing the cell computation specification and propagates the computed values from the terminal nodes to the root node, which represents the next value of the cell state. Each evaluation performed by the evaluator is parameterized by the memory layout and the cell coordinates, so that the evaluator can load cell states from the grid for the appropriate terminal nodes.

The \emph{evaluator} component specifies how the Cellato DSL is interpreted, computing the next state of the grid cells based on the current state and the cell computation specification. Its implementation is tightly coupled with the memory layout to exploit the specific encoding of the state. For example, the evaluator for the bit-plane encoding uses bitwise operations to compute many cells together; it models the cell computation as a series of logical operations, using the bitwise operations as gates in a logic circuit.

The \emph{traverser} component is decoupled from the other components. It defines the order and parallelization of the evaluation of the cell computation specification over the grid. The traversers also enable temporal blocking optimizations, which can improve locality by computing multiple time steps of the cellular automaton together. The most-performant traversers are built for the CUDA backend.

% The library enables users to define cell computation logic independently of memory layouts, evaluation strategies, and traversal patterns, allowing for flexible experimentation with different combinations of these aspects to optimize the performance of cellular automaton simulations on target hardware architectures.
As the library allows users to define cell computation logic independently of specific choices for encoding, evaluation strategies, and traversal patterns, it enables flexible experimentation with different combinations of these aspects to optimize the performance of cellular automaton simulations on target hardware architectures.
